# Decisiones

| ID   | Decisión                                                                                                                                                                                                                                                                             | Motivo                                                                                                        |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| D-01 | pnpm workspaces sin herramientas extra (`pnpm -r`, `--parallel`)                                                                                                                                                                                                                     | Menos dependencias; suficiente para 3 apps.                                                                   |
| D-02 | Contratos con **zod** en `@academy/shared`, tipos inferidos                                                                                                                                                                                                                          | Una sola fuente de verdad; valida en runtime en el cliente; librería ligera y sin deps nativas.               |
| D-03 | Paquetes compartidos compilados a CommonJS (`dist/`)                                                                                                                                                                                                                                 | NestJS corre en CJS; Metro y Vite lo consumen (Vite con `optimizeDeps.include`).                              |
| D-04 | Expo Router con rutas en `src/app` y template recortado (sin reanimated, gesture-handler, web, iOS)                                                                                                                                                                                  | Menor consumo de memoria/tamaño en tablets de 4 GB; se añade solo lo necesario.                               |
| D-05 | `apps/mobile/android/` en `.gitignore`; se genera con `expo prebuild`                                                                                                                                                                                                                | Evita código nativo generado en Git. Revisar (versionar o usar config plugins) al empezar Kotlin.             |
| D-06 | Prisma 7: `prisma.config.ts`, cliente generado en `apps/api/generated/prisma` (ignorado por Git)                                                                                                                                                                                     | Método recomendado por la versión fijada. Falta el adaptador de runtime (`@prisma/adapter-pg`).               |
| D-07 | TypeScript 6 en todo el workspace; Expo SDK 58 / React Native 0.88 / React 19.3.0                                                                                                                                                                                                    | Versiones alineadas con el template oficial de Expo. React web fijado a 19.3.0 para igualar móvil.            |
| D-08 | PostgreSQL 17 en Docker Compose con healthcheck y volumen                                                                                                                                                                                                                            | Único servicio de infraestructura por ahora.                                                                  |
| D-09 | CORS abierto en el API solo para desarrollo                                                                                                                                                                                                                                          | Restringir orígenes antes de producción.                                                                      |
| D-10 | Inter es la tipografía de producto para interfaces web y móvil.                                                                                                                                                                                                                      | Legibilidad consistente en pantallas de tablet y una identidad visual única.                                  |
| D-11 | Un único shell de dashboard (sidebar + topbar + contenido) parametrizado por rol; ver [DASHBOARD](DASHBOARD.md).                                                                                                                                                                     | Permite replicar estudiante/docente/admin cambiando solo navegación y contenido.                              |
| D-12 | Login y sidebar del dashboard comparten la marca (degradado azul, acento naranja `#F67700`, tokens `brand` en `theme`); el área de contenido es sobria (neutros slate, radio 12). Ver [DASHBOARD](DASHBOARD.md) §0.1 y [ESTILO_VISUAL](ESTILO_VISUAL.md).                            | Continuidad visual login → dashboard sin que el azul saturado compita con el contenido.                       |
| D-13 | Sidebar móvil propio con Expo Router (`Slot` + `Pressable`), sin `@react-navigation/drawer`.                                                                                                                                                                                         | El drawer exige gesture-handler y reanimated, excluidos por D-04.                                             |
| D-14 | Web: añadir `react-router` al implementar el shell web (propuesto, aún no instalado).                                                                                                                                                                                                | `apps/web` no tiene enrutador; necesario para navegar entre secciones.                                        |
| D-15 | El rol vive en `@academy/shared` (`roleSchema`); los ítems de navegación e iconos, en cada app.                                                                                                                                                                                      | Rol compartido por API/web/móvil; los iconos difieren por plataforma. Propuesto, pendiente de código.         |
| D-16 | Lenguaje visual del área de trabajo: tarjetas blancas con escena y objetos 3D «arcilla» dibujados en SVG (`Clay3DIcon`, `CourseIllustration`, `SoftScene`) y controles con canto (`Raised3D`); sin imágenes ni dependencias nuevas. Ver [ESTILO_VISUAL](ESTILO_VISUAL.md) §6.1 y §7. | Identidad propia y ligera (cabe en tablets de 4 GB); mismo lenguaje en todas las vistas.                      |
| D-17 | Sin videollamadas en el producto: la ayuda del docente es solicitud + chat. (2026-11-26: el botón «Contactar con docente» lleva el icono de Google Meet por pedido del usuario, pero solo envía la solicitud y abre la pestaña Docente; no hay videollamada ni enlace.)              | Decisión del usuario (2026-11-21); se retiró todo lo de videollamadas del Calendario y del detalle de curso.  |
| D-18 | Desarrollo en Linux nativo (Arch): emulador, `adb`, Metro y repositorio en la misma máquina.                                                                                                                                                                                         | Se abandonó el esquema WSL + Windows (2026-11-26).                                                            |
| D-19 | Refinamiento del alumno según [ESTUDIANTE_UX](ESTUDIANTE_UX.md): espacio de resolución de tareas único (`TaskWorkspace`) compartido por Cursos y Tareas, con historial por tarea; consultar no consume intentos y «Entregar tarea» es la entrega formal.                             | Un solo componente y contexto evita duplicar lógica e historiales.                                            |
| D-20 | Fuente única de datos del alumno: mocks en `features/dashboard/mocks/` y cálculos en `features/dashboard/data/studentSelectors.ts` (promedios sin contar pendientes como cero, avance por lecciones, ventana de ranking); reglas de avance en `data/learningRules.ts`.               | Inicio, Tareas y Progreso muestran las mismas cifras; al llegar la API se cambia la fuente, no las pantallas. |
| D-21 | Se mantiene D-17 (sin videollamadas) aunque ESTUDIANTE_UX §7.1 menciona un enlace de Google Meet facilitado por el docente.                                                                                                                                                          | Decisión previa del usuario; pendiente de que confirme si cambia.                                             |
| D-22 | Calendario **asincrónico** en ambas modalidades: solo eventos con fecha (entregas, asesorías agendadas, simulacros y actividades); sin clases diarias ni solicitudes inmediatas. Ver [ACOMPANAMIENTO_ESCOLAR](ACOMPANAMIENTO_ESCOLAR.md) §2.                                         | Cada alumno avanza a su ritmo; no hay calendario curricular colectivo.                                        |
| D-23 | La modalidad `SCHOOL_SUPPORT` reutiliza el shell, el sidebar y los componentes del alumno con su propia navegación (`schoolSupportNavigation`) y vive en `features/school-support/`. La modalidad viene de la sesión de Codex (`getPortalPath`).                                     | Una sola identidad visual y sin duplicar componentes; la de reforzamiento no cambia.                          |
